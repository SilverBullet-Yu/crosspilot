# 维度 01｜赛事规则是否允许展示（对应清单 P0-4）

核对日期：2026-11-18
核对人：看山工作台（Agent 代为取证，结论需由项目负责人复核后勾选）

## 1.1 预制代码与开发时段

**核查结论：官方手册未设置「禁止预制代码」或「限定开发时段」条款，但设置了等效的原创性与一稿多投红线。**

手册《参赛作品原创与合规规范》原文[^manual]：

> 原创要求：所有参赛作品须为团队独立创作，禁止直接搬运、抄袭网络成品、外包代做、一稿多投（已在其他竞赛获奖 / 公开发布的项目不得参赛）。创作过程建议留存 AI 交互记录、设计底稿、开发日志等素材，主办方有权在评审阶段核验创作真实性，无法提供佐证材料的队伍将取消参赛及评奖资格。

官网 FAQ「可以用已有项目参赛吗？」原文[^site]：

> 参赛作品须为团队独立创作，已获奖或已公开发布的项目不得参赛。……比赛不要求重复造轮子，开源组件可以合规使用，公开创意方向可以参考；但不得搬运完整项目或仅做表面修改，作品的核心功能与主要创新必须由团队独立形成，并如实披露参考和引用情况。

官网 FAQ「是否限制 Agent 开发工具？」：**不限制**，可使用任意习惯的 Agent 开发工具[^site]。

**能说明什么：** S1/S2 式「48 小时极限开发」在 S3 的规则文本中并未写成提交前不得写码的硬约束；提交窗口（12.05 10:00 – 12.07 10:00）是**提交**窗口而非开发窗口。赛前做需求访谈、技术预研和原型，与规则不冲突。
**不能说明什么：** 不能由此推出「可以把已公开发布的旧项目改头换面提交」。CrossPilot 若此前有公开发布版本，属于明确禁止项；且主办方有权核验创作过程佐证，需从现在起保留 AI 交互记录、设计底稿与开发日志。

**对本项目的硬约束：**
1. 需留存开发日志与 AI 交互记录（规则允许核验，无佐证即取消资格）。
2. 作品不得已在其他竞赛获奖或公开发布。
3. 如引用开源组件或参考公开创意，须如实披露。

## 1.2 开放能力使用与配额

手册技术指南列明的免费配额[^manual]：

| 能力 | 单用户上限 | 对本项目的含义 |
| --- | --- | --- |
| 知乎热榜 | 100 次/天 | CrossPilot 不依赖热榜，影响小 |
| 知乎搜索 | 5000 次/天 | 中文侧检索充裕，可支撑演示与多轮调试 |
| 全网搜索 | 手册技术指南未在抓取到的段落中写明数值上限 | 需在配置 Access Secret 后以 `quota` 实测，不以推测填写 |
| 直答 Agent | 100 次/天 | 若把直答放进主链路，演示排练会快速耗尽；建议仅作辅助 |

手册同时写明：依托知乎社区内容创作的项目「需严格遵循知乎开放平台 API 使用规范，**严禁批量爬取、滥用站内用户数据**」[^manual]。

**对本项目的硬约束：** CrossPilot 方案中「知乎侧建立全文库 / RAG 向量库」的设想，与「严禁批量爬取」及接口只返回摘要（见维度 02）叠加后，**不具备合规实现路径**。演示必须改为「实时检索 + 摘录引用 + 链接回源」。

## 1.3 数据展示许可与模拟数据标注

手册《内容红线》原文[^manual]：

> 作品不得包含违反法律法规、公序良俗、低俗色情、造谣引战、侵权盗用、恶意营销导流等内容；不得未经授权使用第三方商标、IP、人像、版权素材。

**核查结论：规则文本未单独规定「演示数据须标注」条款，但「造谣引战」与「侵权盗用」两条红线构成实质约束，且项目自身方案已承诺标注。**

**能说明什么：** 把模拟的德国消费者反馈当作真实结论展示，属于项目自定的合规要求与评审诚信风险，规则层面未给出豁免。
**不能说明什么：** 规则未明确禁止使用模拟数据做演示，因此标注清楚的「演示数据」本身不违规。

**处置：** 演示界面、视频和计划书中，模拟回填结果必须带显式「演示数据」标识，且不与真实反馈混排在同一张证据卡内。

## 1.4 提交材料规定

必交两项、选交两项，截止 12 月 7 日 10:00，截止后不接受任何修改替换[^manual][^site]。网页类作品须提供公网可访问 Demo 链接，设有登录功能时同步提供测试账号密码；推荐接入知乎 OAuth（登录人数计入人气奖）。

**待确认项：** 手册「参赛队伍额外权益」提到每人 800 美元看山工作台 Token 补贴，领取与使用细则需向官方确认，本次未取得独立条款页面。
