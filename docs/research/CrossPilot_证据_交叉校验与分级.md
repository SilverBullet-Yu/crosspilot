## 冲突区

**冲突 1：方案技术设计 vs 平台实际能力**

- 方案 5.1 写有「可选 pgvector / ChromaDB（语义检索）」，叙事上指向把知乎内容做成可检索库。
- 平台事实：搜索 API 无全文、单次≤10 条、无遍历分页；知识库只收文件上传；手册严禁批量爬取。
- **判定：方案侧需要修改。** 三条证据相互独立且方向一致，不存在解释空间。可行形态是「实时检索 + 摘录引用 + 链接回源」，向量库只服务于用户上传的授权资料。

**冲突 2：方案叙事 vs 证据现状**

- 方案 03 节称「知乎在本产品中应承担有明确职责的一侧信息源」。
- 现状：知乎侧实查尚未执行（CLI 未装），德国侧样本为零。
- **判定：不构成方案错误，但构成进度风险。** 「双侧对照」目前只有一侧具备技术可行性，另一侧连样本都没有。

**冲突 3（2026-11-18 实查新增）：手册配额 vs quota 实测**

- 手册技术指南：知乎搜索 5000 次/天、热榜 100 次/天、直答 100 次/天。
- `quota` 实测（本账号当日）：知乎搜索 `TotalQuota=10`、热榜 2、直答 2、全网搜索 10。
- 两者**均为知乎官方来源**，差异达 50–500 倍。
- **判定：不可由本次调研裁定，但容量假设必须以实测为准。** Skill 文档亦明示「实际额度以 `quota` 查询结果为准，不根据固定默认次数推断」。
- **待办**：向官方助手确认当前额度是否为未参赛账号默认值、参赛后是否随 800 美元 Token 补贴提升。该答案直接决定演示架构（是否必须做结果缓存与预跑）。

**无冲突项：** 赛事规则各条款在官网与手册之间表述一致，仅官网 FAQ 更细化。校园宣讲日程两处有差异（手册列 11-18 香港理工大学，本地 Skill 参考文件写清华深圳国际研究生院在 11-18），以官网与手册为准，该差异不影响本项目。

## QA 校验结果与其口径说明

校验脚本 `validate_research_artifacts.py` 曾于 2026-11-18 运行；其自动核验报告因对中文一手条款误报严重（详见下文），已随 2026-11-26 失效材料清理移除，`delivery_mode=framework` 的结论以本文件人工核对为准。

**须注意自动核验的 `verified_facts=0` 不代表本次调研无已验证事实。** 原因是校验器的自动核验规则对中文一手条款不适用：

1. **实体名匹配规则**：要求摘录文本中出现目标实体名或其别名。但规则条款原文不会自称「知乎黑客松 S3」——手册写的是「所有参赛作品须为团队独立创作」，API 文档写的是「ContentText String 是 内容摘要」。摘录越是逐字忠实，越触发该告警。
2. **词元重叠度规则**：基于空格分词计算 claim 与 excerpt 的重叠比例，对中文连写文本会严重低估。
3. **数字匹配规则**：claim 中的「4 项」「三类」等计数词被当作需在原文出现的数值。

因此本文件的「高置信」分层应以人工核对为准：相关摘录均由内置浏览器直读官方页面正文获得，URL、日期与原文已在各维度文件中逐条留痕，可独立回查。`framework` 模式反映的是 P0-1/P0-3 确实缺乏外部证据这一真实状况，与上述分词问题是两回事。
