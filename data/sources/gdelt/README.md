## 二、⚠️ 覆盖不完整 + 时间覆盖极稀（务必先读）

`manifest.json` 中 `coverage_complete: false`、`time_coverage_sparse: true`。

### 2.1 缺口一：2023–2026 窗口未取回

| 项 | 值 |
|---|---|
| 预期半年窗 | 每查询 12 个（2021H1 ~ 2026H2） |
| **实际取回** | **仅 2021H1 ~ 2022H2 共 4 个窗口** |
| 原因 | **GDELT 限速**，2023 年起各窗口全部因 429 放弃 |

### 2.2 缺口二：取回的窗口本身只覆盖几天（更严重）

抓取用了 `sort=datedesc` + `maxrecords=250`，即**从窗口末端向前取 250 条**。高密度查询下 250 条只够几天的量：

| 查询 | 窗口 | 条数 | **实际覆盖天数** | 窗口天数 | 覆盖率 |
|---|---|---|---|---|---|
| `de_luggage_de_lang` | 2021H2 | 42 | 84 | 184 | 45.7% |
| `de_luggage_de_lang` | 2022H2 | 49 | 88 | 184 | 47.8% |
| `en_luggage_de_src` | 2021H1 | 250 | **8** | 181 | **4.4%** |
| `en_luggage_de_src` | 2021H2 | 250 | **11** | 184 | **6.0%** |
| `en_luggage_de_src` | 2022H1 | 250 | **3** | 181 | **1.7%** |
| `en_luggage_de_src` | 2022H2 | 250 | **11** | 184 | **6.0%** |

`en_luggage_de_src` 四窗共 1,000 条，**实际只覆盖 33 天 / 730 天 = 4.5%**。

全表时间覆盖密度实测 **15.1%**（84 个不同日期 / 跨度 557 天）。

### 2.3 由此导出的禁止事项

| 禁止 | 原因 |
|---|---|
| 用本表做**任何跨时间比较或趋势结论** | 各窗覆盖天数差 3–88 天不等，样本不可比 |
| 用本表做**报道量级统计** | 4 个窗口触顶，真实量远大于表中条数 |
| 把 1,090 行当作"2021–2026 的德语媒体覆盖" | 实际是 2021–2022 末端若干天的切片 |

**可以**用于：验证检索式有效性、取少量真实德语标题作定性示例。

### 2.4 正确的补齐方式

| 方案 | 说明 |
|---|---|
| 细化窗口至周粒度 | 250 条上限才不会截断，但请求数 ×26，受限速制约 |
| 改用 `sort=dateasc` 分段游标 | 从窗口起点向后取，配合滚动起点逐段推进 |
| **改用官方 ngrams 数据集** | GDELT 自身对高流量用户的推荐方案，批量下载而非逐窗查询 |

### 2.5 限速实测记录

官方文档称"1 请求/5 秒"，本机实测远比这严格：

| 间隔 | 结果 |
|---|---|
| 9s | 连续 429 |
| 15s | 429, 429, 200 |
| 20s | 200, 429, 429 |
| 25s + 30s 退避 + 75s 冷却 | 仍约每两窗丢一窗 |

GDELT 按客户端 IP 做滑动窗口限速，且与同 IP 其他请求共享配额（并行探测会互相挤占）。TLS 握手本身也慢（9–13s，其他站点 0.1–1.5s）。

## 五、⚠️ 截断警告

`truncated_windows` 记录 **4 个窗口触及 250 条上限**：`en_luggage_de_src` 的全部四个窗口。

这意味着这些半年窗的真实报道量 **大于** 表中条数，表内是按 `datedesc` 排序的前 250 条。**截断与完整返回外观一致**，做量级统计前必须查 `manifest.truncated_windows`，否则会低估覆盖量（这正是硬约束 4 针对的失败模式）。

要取全量须把窗口切得更细（如按月），但限速使之在当前条件下不可行。

## 六、检索式设计说明

长尾德语词在 GDELT 命中极稀疏：实测 `Reisetasche sourcelang:german` 近一个月返回 **0 条**。因此改用品类级宽词：

| 策略 | 说明 |
|---|---|
| `Koffer`（行李箱） | 德语品类词，配 `sourcelang:german` |
| `luggage` + `sourcecountry:GM` | 英文词配德国来源限定。GDELT 把非英语报道机器翻译成英语后索引，故英文词能召回德语原文报道——实测语言字段 97.8% 为 German |

已放弃的检索式：`Rucksack sourcelang:german`、`Reisegepäck sourcecountry:GM`（为压缩请求数而删，限速是硬约束）。

## 七、字段说明

| 列 | 含义 |
|---|---|
| `query_key` / `query` | 对应上表检索式 |
| `half_year` | 半年窗标签，如 `2021H2` |
| `seen_date_utc` | **GDELT 首次发现该文章的时间**，不是发布时间——GDELT 不提供发布时间，精度为 15 分钟 |
| `title` | 标题，截断至 240 字符。GDELT 的分词器有时在标点周围加空格，原样保留 |
| `domain` | 发布站点域名 |
| `source_country` | **发布者所在国**，不等于报道对象国 |
| `language` | 文章语言 |
| `url` | 原文链接 |
| `citation` | 署名文本，许可要求 |

**语言分布**：German 1,066、English 11、French 5、Spanish 3、Russian 2。

## 十、使用约束

- 本数据是**媒体报道标题**，属二手叙述，不含任何消费者原始发言，不构成 L1 证据。
- 可用于"德国媒体对该品类的关注度与时间趋势"，**不可**用于论证具体消费者偏好。
- `services/datasets.py:assert_demand_side("gdelt_doc")` 会拒绝其写入消费者证据侧。
- 引用必须保留 `citation` 列的署名文本。
- 任何基于本表的计数结论，必须同时标注覆盖缺口（2023-2026 缺失）与截断窗口。
